# 离线曲库与本地缓存设计

日期：2025-02-14
项目：WearJelly

## 目标

实现类似 Finamp 的离线曲库：用户连接 Jellyfin 服务器后，后台同步当前账号可见的全部播放列表原数据、歌曲元数据、专辑/艺人关系和图片索引；用户可另外缓存音频和封面。完全断网冷启动时，应用仍能进入本地曲库，浏览播放列表、专辑、艺人和歌曲，并播放已经缓存的音频。

离线模式不得依赖在线 Jellyfin session，也不得为了展示本地曲库发起 HTTP 请求。未缓存歌曲保留在元数据曲库中，但播放时要明确提示需要缓存或联网。

## 参考与现状

Finamp 的离线体验表明，离线播放需要持久化歌曲和父级关系，而不是只保存音频文件。其旧版下载计划记录了多份索引容易失同步，后续方向是使用关系型数据库。本项目当前已有串行下载队列、封面下载、JSON 下载索引和“已缓存音乐”页面，但仍有以下缺口：

- 启动和导航依赖在线 session，无法完全断网冷启动。
- 没有播放列表数据模型和播放列表歌曲顺序关系。
- 下载完成前没有可靠持久化完整歌曲元数据。
- 元数据、媒体文件和图片索引没有统一事务边界。

参考：[Finamp 下载重构计划](https://github.com/finamp-app/finamp/blob/main/DOWNLOADS_PLAN.md)。

## 架构

新增 Room 本地数据库，按规范化服务器地址和用户 ID 隔离数据。数据库为本地曲库的唯一索引来源，音频和图片存储在应用私有目录，数据库保存相对路径和引用关系。

核心实体：

- `ServerProfile`：服务器地址、用户 ID、用户名、最近成功同步时间、离线可用状态。
- `Track`：完整 Jellyfin 歌曲元数据、专辑/艺人关联、音频缓存状态、本地音频相对路径、音质版本和图片引用。
- `Album`：专辑元数据和图片引用。
- `Artist`：艺人元数据和图片引用。
- `Playlist`：播放列表元数据、图片引用和同步时间。
- `PlaylistTrack`：播放列表与歌曲的有序关系，保存服务器顺序。
- `Image`：服务器图片键、类型、tag、下载状态和本地相对路径。
- `DownloadTask`：下载项、状态、进度、失败原因、重试次数和音质版本。

所有关系更新通过 Room 事务完成。同步和下载使用批次或事务边界：只有完整成功的数据才更新 `lastSuccessfulSync` 或缓存状态；失败保留上一次可用快照。

## 同步流程

1. 登录成功后保留现有在线首页，同时启动后台同步任务。
2. 同步当前账号可见的全部播放列表及其歌曲元数据、专辑/艺人关系和封面索引；同步元数据不下载音频。
3. 同步显示状态、进度、最近成功时间和错误原因。
4. 同步失败保留旧快照，并提供重试入口。
5. 重复同步必须幂等，处理播放列表新增、删除、歌曲新增、歌曲移除和顺序变化。
6. 同步不删除用户已经缓存的音频，除非用户明确删除缓存；失去服务器关系的歌曲仍可作为孤立的本地缓存项显示。

## 启动与离线 UX

应用启动先读取本地数据库，不把网络状态作为进入曲库的前置条件：

- 有有效 session 且网络可用：进入在线首页并后台同步。
- 无网络但有本地快照：进入离线首页。
- 没有 session 但有本地快照：进入离线首页，不跳转登录。
- 没有任何本地数据：显示登录页。

离线首页提供播放列表、艺人、专辑和已缓存音乐入口。歌曲显示“已缓存”或“仅元数据”状态；点击未缓存歌曲时提示需要联网并缓存。播放列表显示服务器保存的歌曲顺序和本地封面（若已缓存）。

## 播放与下载

下载任务改为数据库持久化。应用重启时将 `RUNNING` 任务回退为 `WAITING`，恢复串行 worker。音频先写临时文件，完成并校验后原子改名，再在事务中更新歌曲缓存字段；半成品不能被播放器发现。

缓存音质是媒体版本的一部分。切换音质后旧版本不会被误认为当前版本，用户可删除并重新缓存。封面按图片键去重，歌曲、专辑和播放列表可共享图片；只有没有数据库引用时才删除图片。

播放器新增本地 `MediaItem` 构造路径：

- 本地音频存在：直接使用本地文件。
- 本地音频不存在且在线：使用现有 Jellyfin 远程 URL。
- 离线且本地音频不存在：不创建远程 URL，提示用户缓存或联网。
- 本地文件损坏：提示清理缓存并允许重试，不在离线模式隐式联网。

本地封面和本地歌词优先读取；歌词同步作为本地元数据的一部分保存，在线不可用时不影响音频播放。

## 错误与一致性

- 数据库迁移必须有版本号和测试，旧 JSON 索引需要一次性导入或兼容迁移。
- 网络中断、鉴权失败或服务器返回异常时，保留上一次成功快照。
- 下载失败保留失败原因和可重试状态，不写入完成缓存记录。
- 清理缓存同时更新歌曲缓存字段、下载任务和图片引用计数。
- 用户切换服务器或账号时，停止在线播放并切换当前数据库 profile；旧 profile 数据不被误显示。
- 不记录 token、密码或带鉴权参数的 URL。

## 验证

必须覆盖：

- Room migration、事务回滚和重复同步幂等性。
- 播放列表新增、删除、歌曲顺序变化和歌曲元数据更新。
- 应用重启后下载任务恢复。
- 无网络冷启动进入离线首页，且不发起 HTTP 请求。
- 本地音频播放、封面加载、未缓存歌曲提示和损坏文件处理。
- 在线登录、分页、播放队列、歌词和 `verifyNoGms` 回归。
- 454×454 圆屏上的离线入口、播放列表层级、下载状态和错误提示布局。

## 非目标

本次不开发服务器端插件，不修改 Jellyfin 数据，不引入手机伴侣应用，不实现全量音频自动下载，也不改变现有在线播放协议。

## 验收标准

1. 首次连接服务器后，后台能同步全部播放列表原数据，并在 UI 中显示同步状态。
2. 用户未缓存任何歌曲时，断网冷启动仍能浏览播放列表、专辑、艺人和歌曲元数据。
3. 已缓存音频在断网冷启动后可以直接播放，且不请求网络。
4. 播放列表歌曲顺序、封面索引和歌曲元数据在重复同步后保持一致。
5. 下载中断、应用重启、删除缓存和切换音质不会产生半文件或错误的可播放状态。
6. 现有在线登录、播放、歌词、历史、队列、无 GMS 校验和 Wear OS 圆屏适配不回归。
